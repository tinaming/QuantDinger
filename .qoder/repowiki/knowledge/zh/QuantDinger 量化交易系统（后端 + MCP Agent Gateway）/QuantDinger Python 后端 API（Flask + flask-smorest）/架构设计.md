应用采用工厂模式组织：`run.py` 加载 `.env`、设置代理与 UTF-8 编码后调用 `app.create_app()`；`app/__init__.py` 中创建 Flask 实例、注册 SafeJSONProvider（过滤 NaN/Inf）、CORS、日志、数据库初始化（含管理员与内置指标样本），再通过 `register_routes` 挂载人类 API 与 Agent v1 网关。

分层结构清晰：
- `app/routes/` 为 HTTP 路由层，使用 `flask-smorest` 的 Blueprint 声明接口，并通过 `app/openapi/blueprint.py` 中的 `HumanBlueprint` 自动包裹统一成功/错误响应信封（SSE 流式端点除外）；`strategy_blueprint.py` 作为共享蓝图供多个策略子模块复用。
- `app/services/` 是业务逻辑层，按领域拆分子包：`live_trading/`（多交易所 REST 客户端工厂 `factory.py`，支持 Binance/OKX/Bitget/Bybit/Coinbase/Kraken/Gate/HTX/IBKR/MT5/Alpaca，通过 `exchange_id`+`market_type` 解析 demo/testnet/base_url）、`grid/`（网格机器人引擎）、`experiment/`（AI 实验进化）、`bot_scripts/`、`usdt_payment/` 等；顶层还有 `trading_executor`、`backtest_execution`、`strategy_*` 等跨领域服务。
- `app/data_sources/` 提供 K 线/报价数据源抽象，`factory.py` 中的 `DataSourceFactory` 将市场类别归一化到 Crypto/USStock/CNStock/HKStock/Futures/Forex/MOEX 七类并懒加载具体实现，同时支持 crypto 按执行交易所 (`for_exchange`) 分流。
- `app/config/` 集中配置（`settings.py` 用元类从环境变量读取 HOST/PORT/DEBUG/SECRET_KEY/RATE_LIMIT 等）。
- `app/startup.py` 在 app 启动后以进程级单例形式拉起后台任务：挂单 worker、网格成交轮询、组合监控、USDT 支付监听、AI 校准/反思 worker，以及恢复上次运行中的策略。
- `app/data_providers/` 面向上层聚合型数据（情绪、宏观日历、热点图等），与底层 `data_sources` 解耦。
- `app/utils/` 提供认证、缓存、DB、安全沙箱、技术指标等横切工具。
依赖方向：routes → services → data_sources / live_trading factories → 外部交易所/数据源；startup 仅持有进程内单例引用，避免循环导入。
