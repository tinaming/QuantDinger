# 集成缠论 (czsc) 信号到 ChanQuant 策略系统

## 设计思路

czsc 库使用 Rust 实现核心算法，无法在 safe_exec 沙箱中直接 import。采用"预计算桥接"模式：
1. 后端安装 czsc 作为依赖
2. 在指标代码执行前，用 czsc 预计算缠论特征，注入为 DataFrame 列
3. 指标代码像使用 MA/RSI 一样使用 `df['czsc_bi_dir']`、`df['czsc_zs_level']` 等列
4. AI 生成 prompt 中描述可用缠论列，让 LLM 能基于缠论概念生成策略

```
用户请求回测/AI生成
       |
       v
  czsc_bridge.py  <-- 新增：DataFrame -> czsc 预计算 -> 注入缠论列
       |
       v
  safe_exec 沙箱执行指标代码（代码直接使用 df['czsc_*'] 列）
       |
       v
  回测引擎 / 实盘引擎
```

## 变更清单

### 1. 新增 `app/services/czsc_bridge.py` — 缠论预计算桥接层

核心功能：
- `compute_czsc_features(df, freq)` — 接收标准 OHLCV DataFrame，返回附加缠论列的 DataFrame
- `CZSC_COLUMNS` — 所有注入列的命名规范文档
- `get_czsc_column_docs()` — 返回列说明文档（供 AI prompt 使用）
- `is_czsc_enabled()` — 检查 czsc 是否安装可用

注入的列（`czsc_` 前缀）：

| 列名 | 类型 | 说明 |
|------|------|------|
| `czsc_fx_mark` | int | 分型标记: 1=顶分型, -1=底分型, 0=无 |
| `czsc_fx_price` | float | 分型价格（顶分型取 high，底分型取 low） |
| `czsc_bi_dir` | int | 当前笔方向: 1=上升笔, -1=下降笔, 0=无 |
| `czsc_bi_start_price` | float | 当前笔起点价格 |
| `czsc_bi_end_price` | float | 当前笔终点价格 |
| `czsc_bi_length` | int | 当前笔已包含 K 线数 |
| `czsc_zs_level` | int | 当前中枢级别（0=无中枢） |
| `czsc_zs_zd` | float | 中枢最低点 ZD |
| `czsc_zs_zg` | float | 中枢最高点 ZG |
| `czsc_zs_position` | str | 价格相对中枢位置: 'above'/'below'/'inside' |
| `czsc_bs_type` | str | 买卖点类型: '1buy'/'2buy'/'3buy'/'1sell'/'2sell'/'3sell'/'' |
| `czsc_trend` | int | 趋势判断: 1=上涨趋势, -1=下跌趋势, 0=盘整 |

实现要点：
- 使用 `czsc.format_standard_kline(df, freq)` 转换 DataFrame 为 RawBar 列表
- 创建 `CZSC(bars)` 对象执行缠论分析
- 遍历 `bi_list`、`zs_list` 映射回原始 K 线 index
- 频率映射：ChanQuant timeframe -> czsc Freq 枚举
- czsc 不可用时 graceful degrade：返回原 df 不附加列

### 2. 修改 `app/services/backtest.py` — 回测引擎集成

在 `_execute_indicator()` 方法中，在调用 safe_exec 前插入 czsc 预计算：

```python
# 在 _execute_indicator 中，safe_exec 前：
from app.services.czsc_bridge import compute_czsc_features, is_czsc_enabled
if is_czsc_enabled() and self._should_enable_czsc(indicator_code):
    df = compute_czsc_features(df, freq=timeframe)
```

`_should_enable_czsc()` — 检测指标代码是否引用了 `czsc_` 列（简单字符串匹配），避免无谓计算。

### 3. 修改 `app/services/trading_executor.py` — 实盘引擎集成

在实时数据更新后、指标代码执行前，同样调用 `compute_czsc_features()`。

### 4. 修改 `app/routes/indicator.py` — AI 生成 prompt 增强

在 `SYSTEM_PROMPT` 中追加缠论列文档段落：

```
# CZSC (缠论) Columns (available when code references czsc_ prefix)

When the user asks for 缠论/chanlun/Chan signals, the following pre-computed
columns are automatically injected into df. Use them directly:
- df['czsc_fx_mark']: 分型 (1=top, -1=bottom, 0=none)
- df['czsc_bi_dir']: 笔方向 (1=up, -1=down)
... (full list from czsc_bridge.get_czsc_column_docs())
```

### 5. 修改 `app/services/indicator_validation.py` — 验证层适配

在 `generate_mock_df()` 中添加 czsc 模拟列（当 mock df 用于 dry-run 验证时），防止验证阶段因缺少列而报错。

### 6. 修改 `backend_api_python/requirements.txt` — 添加依赖

添加 `czsc>=1.0.0` 作为可选依赖。由于 czsc 需要 Rust 编译环境，考虑：
- 添加在 `requirements.txt` 末尾，带注释说明可选
- 或在 `czsc_bridge.py` 中 try/except import，不可用时 graceful degrade

### 7. 修改 `app/utils/safe_exec.py` — 无需修改

czsc 预计算在后端侧完成，safe_exec 沙箱不需要变更。指标代码只使用 `czsc_` 前缀的 DataFrame 列，这些都是普通数值/字符串列。

## 风险与缓解

1. **czsc 安装失败**：Rust 工具链缺失或编译失败 -> graceful degrade，czsc_bridge 返回原 df
2. **性能开销**：czsc 分析有计算成本 -> `_should_enable_czsc()` 仅在代码引用 czsc_ 列时启用
3. **czsc 版本兼容**：1.0.x API 与 0.9.x 不兼容 -> 锁定 `czsc>=1.0.0`，使用新版 API
4. **数据对齐**：czsc RawBar 与原始 df index 可能偏移 -> 桥接层严格按 index 对齐，缺失值 fillna
